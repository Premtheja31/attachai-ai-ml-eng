# DESIGN_NOTES.md

## Part 2 — the fix, and the multi-turn session flow issue

**What I fixed as #1 (introductions endpoint).** The root cause was that `generate_reason` authenticated the caller but never *authorized* them, and exposed raw attribute rows with no policy. The fix addresses the whole class, not one example: both target members are resolved (404 if missing), both must belong to the caller's club (403 otherwise), and the attribute query itself excludes `restricted == True` and anything below `settings.intro_confidence_threshold` (env-configurable, default 0.6) — so no caller, path, or prompt change can reintroduce the leak. When nothing qualifies, the endpoint says "insufficient basis for an introduction" instead of inventing one.

**The session-flow issue (fixed as the "one more").** In `advance_turn`'s `affirm` branch, `payment_mock_client.charge()` ran before any row was persisted — if the process died between the charge and `db.commit()` (reproducible via `simulate_crash`), the DB had no record a charge happened, the session was still `awaiting_confirmation`, and the client's natural retry charged the card again. The fix inverts the order around the charge: a `Booking` plus a `PaymentAttempt(status="pending", idempotency_key=f"session-{session.id}-attempt-{n}")` are committed *before* the provider call, the charge carries that idempotency key, and the provider (like Stripe) replays the original outcome for a repeated key instead of charging again. On retry, `advance_turn` finds the pending attempt and re-submits the same key; a prior succeeded attempt short-circuits to "confirmed" without any provider call; and session/booking state now follows the charge result, so a failed charge no longer reports a confirmed session.

**Seed script wipe-list.** `scripts/seed.py` could not actually re-run once the session flow had been used — its delete loop omitted `ConversationSession`, so `DELETE FROM bookings` hit the `conversation_sessions.booking_id` FK. Added `ConversationSession` to the wipe list; the seeded data itself is unchanged.
